# Medical Claim Processing Pipeline

A beginner-friendly implementation of the assignment using **FastAPI**, **LangGraph**, **PyMuPDF**, **Pydantic**, and optionally an OpenAI chat model.

> **Important about modes:** The project starts in `LLM_MODE=mock` so that you can launch the API and learn the workflow without an API key. Mock mode uses deterministic text rules and regular expressions; it is a local test harness, not the AI-powered submission mode. Change to `LLM_MODE=openai` and configure `OPENAI_API_KEY` to run AI-based page segregation and extraction.

## 1. Assignment requirements covered

- `POST /api/process` accepts a `claim_id` and a PDF upload as multipart form data.
- The segregator classifies every readable page into the assignment's nine document types: `claim_forms`, `cheque_or_bank_details`, `identity_document`, `itemized_bill`, `discharge_summary`, `prescription`, `investigation_report`, `cash_receipt`, and `other`.
- LangGraph fans out to exactly three extraction agents: ID, Discharge Summary, and Itemized Bill.
- Each agent receives **only the pages assigned to it**, not the complete list of page texts.
- The aggregator combines the results into JSON.
- Bill line-item totals are calculated by Python using `Decimal`, rather than trusting arithmetic generated by an LLM.

The assignment describes the main flow as:

```text
START
  |
  v
Segregator Agent (AI-powered in OpenAI mode)
  |             |                     |
  v             v                     v
ID Agent   Discharge Summary     Itemized Bill
                Agent                Agent
  \             |                    /
   \            |                   /
    +------------+------------------+
                 |
                 v
             Aggregator
                 |
                 v
                END
```

The other six document types are still classified and returned in `document_classification`. Since the assignment asks for exactly three extraction agents, this starter version does not extract prescription, lab report, cash receipt, and `other` page contents.

## 3. Install the tools

### Required

1. **Python 3.11 or 3.12** — install it from [python.org/downloads](https://www.python.org/downloads/). During setup on Windows, enable **Add Python to PATH**.
2. **Visual Studio Code** (recommended, not required) — [code.visualstudio.com](https://code.visualstudio.com/).
3. **Git** (recommended for GitHub submission) — [git-scm.com/downloads](https://git-scm.com/downloads).

No database, Docker, or separate PDF reader library is required. PyMuPDF reads the PDF in Python. This version extracts selectable text; scanned image-only PDFs need OCR, which is listed under limitations below.

### Open the project in a terminal

Extract the project ZIP, then open a terminal in the `claim-processing-pipeline` folder. In VS Code, choose **Terminal → New Terminal**.

### Create a virtual environment

A virtual environment keeps this project's Python packages separate from other projects.

**macOS / Linux:**

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

**Windows PowerShell:**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks activation, either use Command Prompt and run `.venv\Scripts\activate.bat`, or adjust your terminal policy according to your organization's IT guidance. You can also run `.venv\Scripts\python.exe -m pip install -r requirements.txt` without activating.

### Create your `.env` file

Copy `.env.example` to `.env`.

**macOS / Linux:**

```bash
cp .env.example .env
```

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

Keep `LLM_MODE=mock` for the first run. You do not need an API key for this smoke test.

## 4. Run the API locally

From the project root, with the virtual environment active:

```bash
uvicorn app.main:app --reload
```

Expected terminal output includes a local server address, normally `http://127.0.0.1:8000`.

Open these pages in your browser:

- Health check: [http://127.0.0.1:8000/health](http://127.0.0.1:8000/health)
- Interactive API documentation: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

To submit the assignment sample, use `/docs`:

1. Expand **POST `/api/process`**.
2. Click **Try it out**.
3. Enter a value for `claim_id`, such as `CLM-DEMO-001`.
4. For `file`, select the supplied `final (1).pdf`.
5. Click **Execute**.
6. Read the JSON response under **Responses**.

The API expects `claim_id` and `file` as **multipart form data**, which is why Swagger shows two fields. It is not a JSON-only request.

### Optional terminal test with curl

Run from the directory containing your sample PDF (replace the file path as needed):

```bash
curl -X POST "http://127.0.0.1:8000/api/process" \
  -F "claim_id=CLM-DEMO-001" \
  -F "file=@final (1).pdf;type=application/pdf"
```

In Windows PowerShell, Swagger at `/docs` is usually the easiest first test; it handles the file upload form for you.

## 5. Turn on the AI-powered mode

The mock mode lets you validate the end-to-end API without a key. To meet the AI-powered segregator requirement, configure an OpenAI API key and run the real model path.

1. Create an API key in your OpenAI developer account. Never paste it into source code or commit it to Git.
2. Open `.env` in VS Code.
3. Change the settings to something like:

```dotenv
LLM_MODE=openai
OPENAI_API_KEY=put_your_api_key_here
OPENAI_MODEL=gpt-4.1-mini
MAX_UPLOAD_MB=20
MAX_PDF_PAGES=100
```

4. Stop the server with `Ctrl+C` and restart it:

```bash
uvicorn app.main:app --reload
```

5. Upload the PDF again using `/docs`.

The LLM calls use Pydantic structured-output schemas. The exact available model and API access depend on your OpenAI account; if the selected model is not enabled on your account, use a supported chat model and update `OPENAI_MODEL`.

**Privacy and cost:** OpenAI mode sends page text to the configured model provider for classification/extraction and may incur API charges. Use only sample or authorized data, review your organization's data policy, and do not send real patient/financial data to an external provider unless you are allowed to do so. Keep `.env` private.

## 6. How the code works, step by step

### Step 1 — FastAPI receives the upload (`app/main.py`)

`POST /api/process` accepts `claim_id` plus the file. It checks the filename, file size, and PDF header, then passes the PDF bytes to the PDF utility. FastAPI's `/docs` page is generated automatically from the route definition.

### Step 2 — Extract text page by page (`app/pdf_utils.py`)

PyMuPDF opens the PDF and calls `page.get_text("text")` for each page. Every page is stored as `{ "page_number": 1, "text": "..." }`. The page number starts at 1 so that results line up with the PDF viewer. This is preprocessing; the LangGraph's first node is still the segregator.

### Step 3 — Segregator classifies pages (`segregator_node`)

In OpenAI mode, the segregator gets the page numbers and extracted text for the document and returns one of the nine allowed document types for every page, plus a confidence and short reason. The result is normalized so that every input page has exactly one classification. In mock mode, simple keyword rules make the service runnable without credentials.

### Step 4 — LangGraph routes just the relevant pages (`route_to_extraction_agents`)

The router creates three LangGraph `Send` messages:

- **ID Agent:** `claim_forms`, `cheque_or_bank_details`, `identity_document`.
- **Discharge Summary Agent:** `discharge_summary`.
- **Itemized Bill Agent:** `itemized_bill`.

Every `Send` contains only the page subset for that agent. The agent does not receive the other page texts. All three nodes are sent, even if one has an empty page list, so the graph has a predictable join point.

### Step 5 — Each extraction agent returns structured data

- **ID Agent:** patient name, date of birth, IDs, claim/policy details, and visible bank detail fields.
- **Discharge Summary Agent:** patient name, MRN, diagnosis, admission/discharge dates, physician, discharge condition.
- **Itemized Bill Agent:** bill/invoice number, line items, quantities, unit rates, amounts, subtotals, tax and reported totals.

Pydantic schemas describe the expected shapes. In OpenAI mode, they constrain model responses. The code adds source page numbers to the extraction outputs for traceability.

### Step 6 — Totals are recalculated (`_recalculate_bill_totals`)

The bill agent's item amounts are summed in Python with `Decimal` and rounded to cents. The code compares the calculated item sum with a reported subtotal and returns `totals_match`. This avoids relying on the LLM for arithmetic. For multiple bill pages, `combined_line_item_total` is the sum of extracted line items across those documents; it is **not** automatically the final payable amount because separate bills may have taxes, discounts, insurance payments, or patient responsibility.

### Step 7 — Aggregator returns the response

The aggregator combines the classification list and the three agent results under `extracted_data`, then the API returns the result as JSON.

## 8. Troubleshooting

- **`ModuleNotFoundError`:** Activate `.venv` and rerun `pip install -r requirements.txt`.
- **`uvicorn: command not found`:** Run `python -m uvicorn app.main:app --reload`.
- **Port 8000 is already in use:** Run `uvicorn app.main:app --reload --port 8001` and open `http://127.0.0.1:8001/docs`.
- **Missing API key in OpenAI mode:** For your first test, set `LLM_MODE=mock`; for AI mode, add a valid key in `.env` and restart the server.
- **No selectable text:** This starter version does not include OCR. The PDF is likely scanned; convert it to a searchable PDF or add an OCR stage such as Tesseract/AWS Textract/Azure Document Intelligence, subject to privacy approval.
- **Model misses table rows:** Check the structured output against the PDF. LLM extraction should be treated as a draft, especially for claim adjudication; use confidence thresholds and human review in a production system.

## 9. Interview explanation (practice this)

### 60–90 second overview

> “I built a document-processing REST API with FastAPI and LangGraph. The endpoint receives a claim ID and a multi-page PDF. I extract text per page and pass those page representations to a segregator node. The segregator classifies each page into one of nine required document types. LangGraph then fans out to three specialized agents—identity, discharge summary, and itemized bill—using `Send`, so every agent receives only the pages relevant to its task. Each agent returns structured, Pydantic-validated data. An aggregator joins the three results into one JSON response. For financial accuracy, I recalculate line-item totals in Python using `Decimal` instead of trusting an LLM calculation. The project also has a mock mode for local tests and an OpenAI mode for AI-based classification and extraction.”

### Likely interview questions

**Why LangGraph instead of one large prompt?**  
The workflow has separate stages and explicit routing. Specialized agents receive less irrelevant content, can be tested independently, and can be extended without rewriting one giant prompt.

**How do you prevent each agent from seeing the whole PDF?**  
The router filters the per-page objects by classification and uses `Send` with a new state containing only the assigned pages. The extraction nodes read only the `pages` supplied in their message.

**Why Pydantic structured output?**  
It defines the contract for required fields and data types. The application can validate and normalize the result before returning JSON.

**Why use `Decimal` for money?**  
Binary floating-point can represent decimal currency values imprecisely. `Decimal` gives predictable cents-level calculations for billing amounts.

**What happens if a page is ambiguous?**  
The AI segregator can classify it as `other` and return a confidence and reason. Production code should route low-confidence pages to a review queue instead of silently making a claim decision.

**What are the current limitations?**  
This starter version extracts selectable PDF text but has no OCR for image-only scans; extraction should be human-reviewed; it does not include authentication, persistence, deployment, a retry queue, or full production observability.

2. Review the returned classifications and all bill rows against the PDF.
